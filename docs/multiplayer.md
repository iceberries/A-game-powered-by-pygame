# 联机架构与协议

联机模式采用“客户端发送意图，服务端计算结果”的权威服务器模型。客户端不在本地推进角色、敌人或计分规则，只把输入发给服务端，并渲染服务端快照。

每个房间最多 4 名玩家。容量检查与开局检查在同一个服务端锁内完成，因此并发连接也不会超过上限；第 5 名玩家会收到 `room_full` 错误并断开连接。

## 传输协议

底层使用 TCP。每条消息由以下两部分组成：

1. 4 字节无符号大端整数：后续 JSON 的 UTF-8 字节长度；
2. JSON 对象，必须包含 `protocol_version`，当前版本为 `1`。

单条消息最大 1 MiB。增量解码器会同时处理拆包和粘包，不能再直接对一次 `recv()` 的结果调用 `json.loads()`。

客户端消息：

- `chat`：聊天文本，最长 500 个字符；
- `action`：包含严格递增的 `sequence` 与 `move`、`stop_move`、`attack` 或 `quit_game`；
- `ping`：连接测时，服务端回复 `pong`。

服务端消息：

- `welcome`：分配玩家名，并返回 `player_count` 与 `max_players`；
- `system` / `chat` / `error`：大厅与错误消息；
- `game_start`：本局首个完整快照，并通过 `you` 标记本机玩家；
- `sync`：带递增 `tick` 的权威快照；
- `game_end`：本局结束。

## 共享相机

服务端每个快照都会提供 `camera.center`。该位置是所有存活玩家角色中心点的算术平均值，而不是玩家贴图左上角的平均值。所有客户端都使用这个权威中心定位相机，因此四名玩家看到同一个队伍中心；玩家死亡或离开后会自动从中心计算中移除。

## 游戏状态复用

`core/game_rules.py` 是不依赖 Pygame 的共享规则层，单机 `GameLevel` 与纯 `GameWorld` 都从这里取得移动速度、攻击参数、体型衰减、计分和难度曲线。服务端直接运行 `GameWorld.step(commands, dt)`；旧的 `MultiplayerGameLevel` 只保留为兼容名称，不再继承 `GameLevel` 或维护第二套移动、攻击、敌人与碰撞实现。客户端只渲染快照。

## 资源与状态边界

`core/assets.py` 是唯一允许调用 `pygame.image.load` 和创建字体的模块：

- 原始图片按路径只读取一次；
- 动画帧在对象初始化阶段预热；
- 缩放和翻转按 `(path, size, flip)` 缓存；
- 字体按 `(path, size)` 缓存，静态文本渲染结果也会复用。

更新循环中的 `Image.reloade()` 只切换缓存中的 Surface 引用，不再访问磁盘。

`core/state.py` 将原先混在 `const.py` 中的内容拆成三类：

- `GameConfig`：不可变的频率与平衡参数；
- `DisplaySettings`：窗口、全屏和音量；
- `GameSession`：单局分数、击杀数与升级队列，可通过构造函数注入 `GameLevel`。

`const.py` 目前只是旧调用点的兼容入口，不再导入 Pygame 或 `image.py`。

## 线程所有权

| 线程 | 可以做什么 | 不可以做什么 |
| --- | --- | --- |
| 服务端读线程 | `recv`、协议解码、消息校验、写入输入队列 | 修改游戏状态、调用 UI/Pygame |
| 服务端写线程 | 从该客户端发送队列取包并 `sendall` | 读取或推进游戏状态 |
| 服务端模拟线程 | 消费动作队列，以固定 60 Hz 独占推进权威状态，生成快照 | 阻塞等待慢客户端、操作 UI |
| 客户端接收线程 | `recv`、协议解码、写入消息队列 | 创建 Surface、精灵或修改 UI |
| Pygame 主线程 | 消费消息队列，创建/更新渲染对象，处理输入与绘制 | 直接推进联机权威规则 |

所有跨线程数据都通过 `queue.Queue` 交接。快照复制可变的位置和尺寸数组，避免模拟线程与发送线程共享可变对象。客户端连接带“代次”标识，旧连接的迟到断线事件不会关闭新连接。

## 调试与扩展约束

- 新增动作时，同时更新 `validate_client_message()` 和 `MultiplayerSimulation.apply_command()`。
- 新增协议字段时保持旧字段语义不变；不兼容修改应提升 `PROTOCOL_VERSION`。
- Pygame 对象只能在主线程创建和修改。
- 不要从网络线程直接广播游戏状态；服务端模拟线程生成快照，写线程负责实际发送。
- 当前同步频率为 10 Hz、模拟频率为 60 Hz。后续若增加客户端插值，只插值显示位置，不要在客户端重新结算伤害或分数。
